# 4 · Building the reports (PDF)

## How the reference does it

- The report is generated **in the admin's browser** with **jsPDF 2.5.1** and the **Montserrat** font embedded (Light, Regular, SemiBold, Bold), at Letter size (612 × 792 pt).
- The server only supplies the data (`reportData`):
  - ED: the raw answers and the participants' names;
  - ES: the anonymous responses.
- The browser computes the results with the same engines (`ED.score` / `ES.aggregate`), draws the PDF and uploads it (base64). It is stored in Google Drive and then emailed as an attachment.

Renderer entry points (plain JavaScript, no framework):

```js
// assets: fonts (base64) + logos, loaded once
const A = await getPdfAssets('https://…/shared/assets/');      // source/shared/pdfkit.js

// Express Diagnostics
const doc = renderEdPdf(A, 'en', {
  result: ED.score(responses),          // responses: [[67 raw values], …]
  company: 'Acme', participants: ['Ana López', …], dateIso: new Date().toISOString(),
});

// Engagement Survey
const doc = renderEsPdf(A, 'es', {
  agg: ES.aggregate(responses),         // responses: [{answers, importance, area, comments}, …]
  company: 'Acme', launchName: 'Annual survey 2026', invited: 34, dateIso: …, comments: true,
});

doc.output('blob')   // or 'datauristring', 'arraybuffer'
```

The renderers need these globals:
- `window.jspdf` (jsPDF UMD build)
- `ED_I18N` / `ES_I18N`: the texts, which are the same as `texts` in `data/*.json`
- `ED` / `ES`: the engines

`tools/sample-reports.mjs` shows a complete working setup that produced the files in `samples/`.

## Options for your platform

| Option | How | Pros | Cons |
|---|---|---|---|
| **A. Reuse the reference renderers in the browser** *(fastest)* | Your backend returns the report data as JSON (same shape as above). Your admin page loads `jspdf`, the engines, the texts and the renderers, then uploads or downloads the PDF | Pixel-identical to the samples and already tested; no server dependencies | Generated client-side; the texts must be shipped to the page |
| **B. Reuse the same renderers on the server (Node.js)** | Run the same files in Node: jsPDF works in Node. Load them with a small wrapper that defines the globals, or run a headless browser as `tools/sample-reports.mjs` does | Identical output; reports can be generated by jobs or emailed automatically | Needs Node on the server |
| **C. Rebuild as HTML/CSS templates → PDF** | Render each page as HTML (your stack's templates), then print with a headless browser (Playwright / Puppeteer `page.pdf()`) or a service like Gotenberg / WeasyPrint. Radars and bars as inline SVG | Easiest for your team to restyle and maintain; text selectable; any language | More work up front; you must match the samples yourself |

**Recommendation:** start with **A** or **B**. They give you identical, already-verified reports on day one. Move to **C** only if you need to restyle reports often. Whatever you pick, compute the numbers with the engines (or a verified port) and keep the PDF layer “dumb”: it only draws what the engine returns.

## Layout notes that are easy to miss

- Section headings have a short **red vertical bar** on the left.
- **Express Diagnostics with one participant:**
  - the frame legend is omitted;
  - swatches are outlined in their status colour instead of the frame style;
  - the cover says “Participants” instead of “Participants surveyed: n”.
- ED radars:
  - the 100% radius is the outer ring;
  - the dotted rings at 75% (green) and 50% (red) are the norms;
  - axis labels carry the percent in the status colour.
- ED key-factor section: every statement shows the **zone wording**, not the participant wording, except for zone 0 (nobody could answer), which shows the base statement + “· no answer”.
- ES area table:
  - at most 5 data columns per table, with the Company column repeated;
  - long row labels wrap (Spanish: “Totalmente comprometido + Comprometido”).
- ES “All questions” and “What matters most” bars show **% labels** inside segments that are wide enough.
- Page breaks never split a single statement or question; a section that continues shows “(cont.)”.
- File name used by the reference:
  - `Express-Diagnostics-<company>-<yyyy-mm-dd>.pdf` (Spanish: `Diagnostico-Expres-…`)
  - `Engagement-Survey-<company>-<yyyy-mm-dd>.pdf` (Spanish: `Encuesta-de-Compromiso-…`)
